# Структура проекта

## Точки входа

- `main.py` — запуск desktop-приложения через `python main.py`. Здесь нет бизнес-логики. Совместимые импорты сохранены для существующих инструментов.
- `pslounge/web.py` — Flask-приложение и HTTP-маршруты. Для разработки: `python -m flask --app main run`. Это другой способ запуска того же API, без открытия desktop-браузера.
- `static/app.js` — единственная точка запуска браузера: инициализация состояния, привязка экрана лицензии, проверка лицензии.

Функции больше не подменяются в конце файлов. У ES-модулей нет автоматического запуска приложения при импорте.

## Backend

| Модуль | Ответственность |
| --- | --- |
| `constants.py`, `paths.py` | Константы, пути исходного/упакованного приложения, журнал |
| `desktop.py` | Единственный экземпляр, выбор порта, браузер, desktop-запуск через Waitress |
| `licensing.py` | Идентификатор устройства, проверка и сохранение лицензии |
| `formatting.py` | Нормализация и форматирование дат, денег, типов и оплат |
| `state.py` | Проверка и чтение старых JSON для миграции, совместимые утилиты |
| `business/` | SQLite, аккаунты, смены, неизменяемые оплаты, склад, абонементы и резервирование |
| `report_data.py` | Преобразование сессий и начислений в строки отчёта, фильтры |
| `excel.py` | Общие стили, таблицы, диаграммы, текстовые значения XLSX |
| `reports/shift.py` | Отчёт за смену |
| `reports/period.py` | Отчёт за период |
| `reports/audit.py` | Проверки согласованности и аналитика отчёта |
| `web.py` | HTTP-запросы, ошибки, выдача XLSX |

`workbooks.py` сохраняет совместимые импорты двух построителей. Windows-данные отделены от EXE в AppData, ресурсы остаются в сборке; спецификация PyInstaller включает весь каталог `static`.

Рабочее состояние хранится в SQLite; запись выполняется транзакцией BEGIN IMMEDIATE с проверкой revision и ключом повторной команды. Оплаты и аудит имеют запрет UPDATE/DELETE. Сохраняются 31 последний снимок состояния, полная история сессий и финансовых операций остаётся в основной базе. JSON-процедуры ниже используются для чтения старых данных и совместимых инструментов.

Сравнение версии и запись старого JSON backup сериализуются одним `RLock` в процессе. Временные файлы уникальны и заменяются атомарно. Повреждённый primary не заменяет исправный backup. Если primary и backup невалидны, выбирается последний валидный дневной snapshot.

## Frontend

ES-модули находятся в `static/js/`:

- `state.js` — явное общее состояние и его инициализация; `defaults.js` — начальные настройки; `achievement-definitions.js` — декларативный каталог достижений;
- `stations.js` — определения, порядок, типы, изображения и начальное состояние станций;
- `sessions.js`, `session-actions.js`, `session-recovery.js` — финансовые записи, действия оператора, восстановление;
- `business-api.js`, `business-auth.js`, `business-ui.js` — доступ сотрудников, касса и коммерческие функции; `storage.js` — безопасный кэш;
- `persistence.js` — localStorage и синхронизация с диском;
- `settings-model.js`, `settings-editor.js`, `settings-access.js` — данные настроек, редактор, PIN;
- `reports.js`, `report-calendar.js`, `report-export.js` — данные и отображение отчётов, календарь, загрузка файлов;
- `achievements.js`, `journal.js`, `license.js` — соответствующие функции;
- `runtime.js`, `ui-events.js`, `ui-rendering.js`, `notifications.js`, `ui-utils.js` — запуск таймеров, события, отрисовка, звук и утилиты.

Импорты показывают зависимости; `state` импортируется как `appState`, чтобы не конфликтовать с локальными переменными. Некоторые модули имеют циклические зависимости из-за существующей связи моделей и интерфейса. Циклы безопасны при текущей схеме: при импорте объявляются функции, а инициализация выполняется после загрузки всего графа. Это промежуточная архитектура: выделение независимых моделей и контроллеров позволит убрать циклы в следующем рефакторинге.

## Проверки

`python tools/run_checks.py` выполняет публичные backend- и JavaScript-проверки. `--ui` дополнительно запускает Chromium. Скрипт использует `.venv`, если она существует, иначе текущий Python. Он завершается с кодом первого неуспешного шага.

`tests/` содержит регрессии параллельного сохранения, повреждённых файлов, восстановления, формата XLSX и клиентской синхронизации. Проверки в `tools/*_check.cjs` импортируют реальные ES-модули вместо извлечения фрагментов исходного текста.

`tools/frontend_smoke_check.cjs` запускает настоящий Flask-сервер, проверяет настоящий экран без лицензии и затем использует подставные HTTP-ответы лицензии/backup для UI-сценария. Он не создаёт подписанную лицензию и не подтверждает работу лицензированных backend-маршрутов. Тесты лицензии и полного состояния остаются отдельными и требуют существующего приватного тестового ключа.

`/demo` запускает отдельный браузерный сценарий с учебными данными и отдельным пространством кэша; реальное API сохраняет лицензионную проверку, вход и CSRF. `/about` — страница продукта. `tools/business_test_server.py` изолирует тестовую базу и подменяет проверку лицензии только в тестовом процессе; production-флага обхода лицензии нет.
